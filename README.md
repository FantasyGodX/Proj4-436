# Quest Board API

A REST API for a fantasy quest board: post quests, claim them, and mark them complete. Built with Express (ES modules), TypeScript, and a Supabase Postgres database, and deployed to Vercel as a serverless function.

**Live URL:** `https://proj4-436.vercel.app`
**Try it:** `GET https://proj4-436.vercel.app/quests`

> **Free-tier wake-up delay:** this API runs on free tiers. The first request after a period of inactivity can take several seconds (or longer) to respond, because Vercel has to start the serverless function (a cold start) and a free Supabase project that has been idle for about a week is paused and must wake up. If the first request is slow or fails, wait a few seconds and send it again; later requests are fast.

## Tech

- Express 5, ES modules (`"type": "module"`, `import` everywhere)
- Supabase (Postgres) via `@supabase/supabase-js`, typed with generated types
- TypeScript (run by `tsx` locally, compiled by Vercel in production)

## Run locally

Requires Node 22 or newer.

1. Install dependencies:
   ```bash
   npm install
   ```
2. Create the table: open your Supabase project, go to **SQL Editor**, paste in [supabase/schema.sql](supabase/schema.sql), and run it.
3. Create your env file:
   ```bash
   cp .env.example .env
   ```
   Fill in `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` (Supabase dashboard, Project Settings, API Keys). The service key is a secret: it stays in `.env` (git-ignored) and in Vercel's settings, never in code.
4. Start the server:
   ```bash
   npm run dev
   ```
   Open http://localhost:3000/api/health.

Other scripts: `npm run typecheck` runs the TypeScript compiler, `npm run gen:types` regenerates the Supabase types (edit the project ref in `package.json` first, and run it again after every schema change).

## Data model

A **quest** looks like this:

| Field         | Type           | Notes                                           |
| ------------- | -------------- | ----------------------------------------------- |
| `id`          | uuid           | Generated by the database                       |
| `title`       | string         | Required, 1 to 120 characters                   |
| `description` | string or null | Optional                                        |
| `status`      | string         | `open` (default), `claimed`, or `completed`     |
| `difficulty`  | string         | `easy` (default), `medium`, or `hard`           |
| `reward_gold` | integer        | 0 or more, default 0                            |
| `claimed_by`  | string or null | Name of the adventurer who claimed it           |
| `created_at`  | timestamp      | Set by the database                             |
| `updated_at`  | timestamp      | Updated on every PUT and PATCH                  |

## Endpoints

All bodies are JSON (`Content-Type: application/json`). All errors look like `{ "error": "message" }`.

### `GET /`

Returns the API name and a list of available endpoints.

Response `200`:
```json
{
  "name": "Quest Board API",
  "endpoints": ["GET /api/health", "GET /quests", "GET /quests/:id", "POST /quests", "PUT /quests/:id", "PATCH /quests/:id", "DELETE /quests/:id"]
}
```

### `GET /api/health`

Response `200`:
```json
{ "status": "ok" }
```

### `GET /quests`

Returns an array of quests. Optional query parameters:

| Param        | Values                                                         | Default      |
| ------------ | -------------------------------------------------------------- | ------------ |
| `status`     | `open`, `claimed`, `completed`                                 | all          |
| `difficulty` | `easy`, `medium`, `hard`                                       | all          |
| `sort`       | `created_at`, `title`, `reward_gold`, `difficulty`, `status`   | `created_at` |
| `order`      | `asc`, `desc`                                                  | `desc`       |
| `limit`      | integer from 1 to 100                                          | no limit     |

Example: `GET /quests?status=open&sort=reward_gold&order=desc&limit=2`

Response `200`:
```json
[
  {
    "id": "5b8f1c52-0d0a-4a49-9f49-1d6a3d1f0c11",
    "title": "Retrieve the Lost Amulet",
    "description": "An amulet was lost in the Whispering Caves.",
    "status": "open",
    "difficulty": "hard",
    "reward_gold": 300,
    "claimed_by": null,
    "created_at": "2026-11-21T22:10:31.512Z",
    "updated_at": "2026-11-21T22:10:31.512Z"
  }
]
```

An invalid value for any parameter returns `400`.

### `GET /quests/:id`

Response `200`: a single quest object (same shape as above).
Response `400` if `:id` is not a UUID. Response `404` if no quest has that id.

### `POST /quests`

Creates a quest. Only `title` is required.

Body:
```json
{
  "title": "Defeat the Bridge Troll",
  "description": "A troll is charging tolls at Old Stone Bridge.",
  "difficulty": "medium",
  "reward_gold": 150
}
```

Response `201`:
```json
{
  "id": "0c9e7a8e-3a35-4f6b-8f0b-2f3f4f6a9c77",
  "title": "Defeat the Bridge Troll",
  "description": "A troll is charging tolls at Old Stone Bridge.",
  "status": "open",
  "difficulty": "medium",
  "reward_gold": 150,
  "claimed_by": null,
  "created_at": "2026-11-21T22:15:02.114Z",
  "updated_at": "2026-11-21T22:15:02.114Z"
}
```

Response `400` for a missing title, wrong types, unknown fields, or malformed JSON:
```json
{ "error": "title is required; unknown field(s): foo; reward_gold must be a non-negative integer" }
```

### `PUT /quests/:id`

Replaces a quest. `title` is required; any other field you leave out is reset to its default (`description` and `claimed_by` to null, `status` to `open`, `difficulty` to `easy`, `reward_gold` to 0).

Body:
```json
{ "title": "Defeat the Bridge Troll (revised)", "difficulty": "hard", "reward_gold": 250 }
```

Response `200`: the updated quest. `400` for a bad body or id. `404` if the quest does not exist.

### `PATCH /quests/:id`

Updates only the fields you send. At least one field is required.

Body:
```json
{ "status": "claimed", "claimed_by": "Aria" }
```

Response `200`:
```json
{
  "id": "0c9e7a8e-3a35-4f6b-8f0b-2f3f4f6a9c77",
  "title": "Defeat the Bridge Troll",
  "description": "A troll is charging tolls at Old Stone Bridge.",
  "status": "claimed",
  "difficulty": "medium",
  "reward_gold": 150,
  "claimed_by": "Aria",
  "created_at": "2026-11-21T22:15:02.114Z",
  "updated_at": "2026-11-21T22:20:45.870Z"
}
```

Response `400` for an empty or invalid body. `404` if the quest does not exist.

### `DELETE /quests/:id`

Response `200`:
```json
{
  "message": "Quest deleted",
  "quest": { "id": "0c9e7a8e-3a35-4f6b-8f0b-2f3f4f6a9c77", "title": "Defeat the Bridge Troll", "...": "..." }
}
```

Response `404` if the quest does not exist.

### Status codes

| Code | Meaning                                                              |
| ---- | -------------------------------------------------------------------- |
| 200  | Success                                                              |
| 201  | Created (POST)                                                       |
| 400  | Bad input: invalid JSON, body, id, or query parameter                |
| 404  | Quest or route not found                                             |
| 500  | Server or database problem (details are logged, not sent to client)  |

## Request collection

[requests/quests.http](requests/quests.http) contains a request for every endpoint, plus error cases. Open it in VS Code with the REST Client extension and click "Send Request". Change `baseUrl` at the top to test the live site.

## Deploying to Vercel

1. Push this repo to GitHub.
2. At vercel.com/new, import the repo. Vercel detects Express; leave build settings alone.
3. In **Project Settings, Environment Variables**, add `SUPABASE_URL` and `SUPABASE_SERVICE_KEY`.
4. Redeploy (Deployments tab, three dots, Redeploy) so the variables apply.

The entry file is [src/index.ts](src/index.ts). It ends with `export default app`, and only calls `app.listen` when `process.env.VERCEL` is not set.

## Project structure

```

  routes/quests.ts      the five CRUD endpoints
  middleware/           logger and centralized error handler

  lib/errors.ts         HttpError class
```
